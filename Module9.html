1.3 The Feature Engineering Hierarchy (From Easy to Advanced)

Level 1: ✅ Basic Cleaning
  • Handle missing values (impute with mean/median/mode)
  • Remove duplicates and constant columns
  • Fix data types (dates as datetime, categories as category)
  • Rename columns for clarity
💡 80% of real-world data issues are solved here
Level 2: 📐 Scaling & Transformations
  • Standardization (z-score): (x - μ) / σ
  • Normalization (min-max): (x - min) / (max - min)
  • Log transform for skewed distributions
  • Box-Cox / Yeo-Johnson for normality
Level 3: 🧩 Interaction & Polynomials
  • Multiplication: X1 × X2 (synergy effects)
  • Division: X1 / X2 (ratios, normalization)
  • Polynomial: X², X³ (curvature)
  • Difference: X1 - X2 (distance, change)
Level 4: 📊 Aggregation & Statistics
  • Group-by aggregations: mean, median, std, count
  • Rolling windows (time series)
  • Ratio to group average
  • Rank within group
Level 5: 🧠 Domain-Specific
  • Distance calculations (Haversine for geo)
  • Text features (TF-IDF, word embeddings)
  • Date features (hour, day, month, season, is_holiday)
  • Business rules (customer lifetime value)

2.1 What Are Interaction Features?

Interaction features capture the combined effect of two or more variables that cannot be explained by each variable alone. In real-world data, features rarely act independently — they work together in complex ways.

📖 The Core Concept: An interaction occurs when the effect of one feature on the target depends on the value of another feature. For example, the impact of square footage on house price is MUCH larger in a good neighborhood than a bad one.
\[ \text{Interaction Feature} = X_i \times X_j \quad \text{or} \quad X_i \div X_j \quad \text{or} \quad X_i - X_j \]
📊 Types of Interactions
TypeFormulaReal-World Example
MultiplicativeX₁ × X₂sqft × location_score (big house in great area = premium price)
RatioX₁ ÷ X₂price ÷ sqft = price_per_sqft (normalizes for size)
DifferenceX₁ - X₂current_price - purchase_price = profit
LogicalX₁ AND X₂has_garage AND has_basement (amenity combination)
🏠 Real Estate Example

Without interaction: Price = 100×sqft + 50000×location

With interaction: Price = 100×sqft + 50000×location + 20×sqft×location

The interaction term means: for each extra sqft, the value is 20×location_score higher — location amplifies sqft value!

💡 This captures the synergy that raw features miss.

❌ Without Interaction (Additive Model)
\[ y = \beta_0 + \beta_1 x_1 + \beta_2 x_2 \]

Lines are parallel — the effect of x₁ is the same regardless of x₂. This rarely matches reality!

✅ With Interaction (Multiplicative Model)

Lines cross — the effect of x₁ CHANGES based on x₂ value. This captures real-world complexity.

💡 The interaction term allows the slope for x₁ to vary with x₂!

2.3 Polynomial Features: Capturing Curves with Linear Models

Polynomial features allow linear models to fit non-linear relationships by adding powers of existing features (x², x³, etc.). This transforms a linear model into a polynomial regression.

\[ \text{Polynomial of degree d: } y = \beta_0 + \beta_1 x + \beta_2 x^2 + \beta_3 x^3 + \dots + \beta_d x^d \]
📈 Degree 1 (Linear)
\[ y = \beta_0 + \beta_1 x \]

Straight line — too simple for most real data.

📈 Degree 2 (Quadratic)
\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 \]

U-shaped or inverted-U — captures diminishing returns.

📈 Degree 3 (Cubic)
\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 + \beta_3 x^3 \]

S-shaped — captures increasing then decreasing trends.

⚠️ Warning: The Curse of Dimensionality with Polynomials

With 10 original features, degree=2 creates 55 features! Degree=3 creates 286 features! Always combine polynomial features with feature selection (Module 8).

\[ \text{Number of polynomial features} = \binom{n + d}{d} \]

Where n = original features, d = degree. For n=20, d=3 → 1,771 features!

2.5 Mathematical Deep Dive: Why Interactions Work

📐 The Math Behind Interactions

Without interaction (additive model):

\[ E[Y|X_1, X_2] = \beta_0 + \beta_1 X_1 + \beta_2 X_2 \]

With interaction (multiplicative model):

\[ E[Y|X_1, X_2] = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \beta_3 (X_1 \times X_2) \]

The partial derivative (effect of X₁ on Y) becomes:

\[ \frac{\partial Y}{\partial X_1} = \beta_1 + \beta_3 X_2 \]

Key insight: The effect of X₁ now DEPENDS on X₂'s value!

📈 Polynomial Regression Math

Quadratic model:

\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 \]

The derivative (slope) changes with x:

\[ \frac{dy}{dx} = \beta_1 + 2\beta_2 x \]

Interpretation:

  • If β₂ > 0: curve opens UP (U-shaped, increasing returns)
  • If β₂ < 0: curve opens DOWN (∩-shaped, diminishing returns)
  • Vertex at x = -β₁/(2β₂)

2.6 When to Use Interactions & Polynomials?

✅ Use Interactions When:
  • You suspect synergy between features (e.g., advertising × season)
  • Domain knowledge suggests combined effects
  • Residual plots show patterns across feature combinations
  • Linear model underperforms on test data
  • Features have complementary or multiplicative relationships
✅ Use Polynomials When:
  • Relationship between X and Y is curved (check scatter plot)
  • Diminishing returns or saturation effects exist
  • U-shaped or inverted-U patterns present
  • Residuals show systematic pattern vs fitted values
⚠️ Avoid When:
  • Feature count is already high (risk of overfitting)
  • Sample size is small (n < 10 × new features)
  • Tree-based models already capture interactions naturally
  • You haven't applied feature selection after creation
💡 Pro Tip: For tree-based models (Random Forest, XGBoost), explicit interaction features are LESS critical because trees automatically capture interactions through splits. For linear models, they are ESSENTIAL!

  • ☐ Start with degree=2 polynomials (x² is often enough)

3.1 Why Transform Numerical Features?

Feature transformations modify the distribution or scale of numerical features to make them more suitable for machine learning models. Many models (linear regression, SVM, neural networks) assume normally distributed data or specific scales.

📖 The Core Problem: Real-world data is rarely normally distributed. It often has skewness (long tails), outliers, or non-linear relationships with the target. Transformations fix these issues.
🎯 Goals of Transformation
  • ✅ Make distribution more symmetric (reduce skewness)
  • ✅ Stabilize variance (homoscedasticity)
  • ✅ Make relationships more linear
  • ✅ Reduce impact of outliers
  • ✅ Make data scale-invariant
⚠️ Signs You Need Transformations
  • 📊 Skewness > 1 or < -1 (highly skewed)
  • 📈 Residual plots show funnel shapes (heteroscedasticity)
  • 🎯 Model performs poorly on extreme values
  • 📉 Features have vastly different scales

3.2 Log Transformation: The Most Important Transform

\[ x' = \log(x + 1) \quad \text{or} \quad x' = \ln(x) \quad \text{or} \quad x' = \log_{10}(x) \]

The log transformation is the most commonly used transformation for right-skewed data (long tail on the right). It compresses large values and expands small values.

3.3 Box-Cox Transformation: The Optimal Power Transform

\[ x^{(\lambda)} = \begin{cases} \frac{x^\lambda - 1}{\lambda} & \text{if } \lambda \neq 0 \\ \ln(x) & \text{if } \lambda = 0 \end{cases} \]

The Box-Cox transformation automatically finds the optimal power parameter λ that makes the data as normally distributed as possible. It's a family of power transforms that includes log, square root, and inverse as special cases.

3.4 Square Root & Cube Root Transformations

\[ \text{Square root: } x' = \sqrt{x} \quad \text{Cube root: } x' = \sqrt[3]{x} \]
📊 Square Root (λ = 0.5)

Best for: Count data, Poisson-distributed variables (e.g., number of visits, defects, accidents)

Effect: Less aggressive than log, still handles moderate skewness

💡 Perfect for count data where variance ≈ mean
📊 Cube Root (λ = 1/3)

Best for: Data with zeros, moderate skewness, or negative values

Effect: Handles zeros naturally (unlike log), preserves sign

💡 Works well for financial returns and percentage changes

3.5 Scaling & Normalization: Bringing Features to Same Scale

📏 Standardization (Z-Score)
\[ z = \frac{x - \mu}{\sigma} \]

Result: Mean = 0, Standard Deviation = 1

When to use: Linear regression, SVM, neural networks, PCA, k-means

Robust to outliers? No (use RobustScaler instead)

📏 Min-Max Normalization
\[ x_{norm} = \frac{x - \min(x)}{\max(x) - \min(x)} \]

Result: Range [0, 1] (or [-1, 1] with feature_range)

When to use: Neural networks (sigmoid/tanh), image pixels, bounded features

Robust to outliers? No (outliers compress the range)

🛡️ Robust Scaling
\[ x_{robust} = \frac{x - \text{median}(x)}{\text{IQR}(x)} \]

Result: Uses median and IQR (interquartile range)

When to use: Data with many outliers

Robust to outliers? Yes! (uses percentiles)

📊 Scaling Decision Tree:
  • ➡️ Neural networks? → MinMaxScaler [0,1] or [-1,1]
  • ➡️ Linear models / SVM / PCA? → StandardScaler
  • ➡️ Many outliers? → RobustScaler
  • ➡️ Sparse data? → Don't scale (preserve zeros)

3.6 Binning / Discretization: Converting Continuous to Categorical

Binning converts a continuous feature into discrete intervals (bins). This can help capture non-linear relationships and reduce the impact of measurement noise.

📊 Equal-Width Binning
\[ \text{bin width} = \frac{\max(x) - \min(x)}{\text{n\_bins}} \]

Divides range into equal-sized intervals.

Example: Age [0-20], [20-40], [40-60], [60-80]

⚠️ Sensitive to outliers (one bin may be empty or huge)
📊 Equal-Frequency (Quantile) Binning

Each bin contains approximately the same number of samples.

Example: Income: bottom 25%, 25-50%, 50-75%, top 25%

💡 Better for skewed distributions — ensures balanced bins
📊 Custom / Domain Binning

Bins defined by business rules or domain knowledge.

Example: Age: Child (0-12), Teen (13-19), Adult (20-64), Senior (65+)

💡 Most interpretable for business stakeholders

3.9 Common Pitfalls & How to Avoid Them

3.10 Transformations & Binning: Best Practices

✅ DO's
  • ☐ Always visualize distributions before transforming
  • ☐ Fit transformations ONLY on training data
  • ☐ Save fitted transformers for production
  • ☐ Use log1p for data with zeros: np.log1p(x)
  • ☐ Apply inverse transform to interpret predictions
  • ☐ Use Pipeline to prevent leakage
❌ DON'Ts
  • ✗ Don't transform categorical features
  • ✗ Don't apply Box-Cox to negative data
  • ✗ Don't use equal-width binning with outliers
  • ✗ Don't forget to handle zeros before log
  • ✗ Don't transform without validating impact

4.1 Advanced Encoding

📌 Target Encoding (Mean Encoding)

Replace category with mean of target. Must use smoothing and cross-validation to avoid leakage.

\[ \text{encoded} = \frac{\text{mean(target)} \times n + \text{global_mean} \times \alpha}{n + \alpha} \]
📊 Frequency Encoding

Replace category with count/frequency. Works well for high-cardinality.

🏷️ One-Hot & Ordinal

One-hot for low cardinality, ordinal for ordered categories.

5.1 Golden Rules: No Leakage!

⚠️ Critical: Fit transformations (e.g., scaling, bin edges, target encoding) ONLY on training data, then transform test/validation.
# ✅ CORRECT
scaler = StandardScaler().fit(X_train)
X_train_scaled = scaler.transform(X_train)
X_test_scaled = scaler.transform(X_test)

# ❌ WRONG (leakage)
X_scaled = scaler.fit_transform(X)  # uses test info
X_train, X_test = split(X_scaled)

5.2 Common Pitfalls

  • Curse of dimensionality from polynomial/interaction features → combine with feature selection (Module 8).
  • Target leakage when creating features using future information.
  • Overfitting complex features without cross-validation.
  • Not handling outliers before binning/transformations.

6.3 Target Encoding (Safe)

from sklearn.model_selection import StratifiedKFold
import pandas as pd

def target_encode(train, test, col, target, n_folds=5):
    skf = StratifiedKFold(n_splits=n_folds, shuffle=True)
    train_encoded = np.zeros(len(train))
    for idx, (train_idx, val_idx) in enumerate(skf.split(train[col], train[target])):
        mean_target = train.iloc[train_idx].groupby(col)[target].mean()
        train_encoded[val_idx] = train.iloc[val_idx][col].map(mean_target)
    global_mean = train[target].mean()
    test_encoded = test[col].map(train.groupby(col)[target].mean()).fillna(global_mean)
    return train_encoded, test_encoded

7.1 Knowledge Check

❓ When should you use polynomial features?

Answer
When linear model underfits and you suspect non-linear relationships, but feature count small.

❓ What is target leakage?

Answer
Using information from the target variable that would not be available at prediction time (e.g., future data).

7.2 Summary

  • ✅ Feature engineering transforms raw data into powerful predictors.
  • ✅ Interaction (×, /) and polynomial (x²) features capture non-linear patterns.
  • ✅ Log/Box-Cox handle skewness; binning captures stepwise effects.
  • ✅ Target encoding works well for high-cardinality but needs CV to prevent leakage.
  • ✅ Domain-specific features often provide the biggest lift.
