1.3 The Feature Engineering Hierarchy (From Easy to Advanced)

Level 1: ✅ Basic Cleaning
  • Handle missing values (impute with mean/median/mode)
  • Remove duplicates and constant columns
  • Fix data types (dates as datetime, categories as category)
  • Rename columns for clarity
💡 80% of real-world data issues are solved here
Level 2: 📐 Scaling & Transformations
  • Standardization (z-score): (x - μ) / σ
  • Normalization (min-max): (x - min) / (max - min)
  • Log transform for skewed distributions
  • Box-Cox / Yeo-Johnson for normality
Level 3: 🧩 Interaction & Polynomials
  • Multiplication: X1 × X2 (synergy effects)
  • Division: X1 / X2 (ratios, normalization)
  • Polynomial: X², X³ (curvature)
  • Difference: X1 - X2 (distance, change)
Level 4: 📊 Aggregation & Statistics
  • Group-by aggregations: mean, median, std, count
  • Rolling windows (time series)
  • Ratio to group average
  • Rank within group
Level 5: 🧠 Domain-Specific
  • Distance calculations (Haversine for geo)
  • Text features (TF-IDF, word embeddings)
  • Date features (hour, day, month, season, is_holiday)
  • Business rules (customer lifetime value)

2.1 What Are Interaction Features?

Interaction features capture the combined effect of two or more variables that cannot be explained by each variable alone. In real-world data, features rarely act independently — they work together in complex ways.

📖 The Core Concept: An interaction occurs when the effect of one feature on the target depends on the value of another feature. For example, the impact of square footage on house price is MUCH larger in a good neighborhood than a bad one.
\[ \text{Interaction Feature} = X_i \times X_j \quad \text{or} \quad X_i \div X_j \quad \text{or} \quad X_i - X_j \]
📊 Types of Interactions
TypeFormulaReal-World Example
MultiplicativeX₁ × X₂sqft × location_score (big house in great area = premium price)
RatioX₁ ÷ X₂price ÷ sqft = price_per_sqft (normalizes for size)
DifferenceX₁ - X₂current_price - purchase_price = profit
LogicalX₁ AND X₂has_garage AND has_basement (amenity combination)
🏠 Real Estate Example

Without interaction: Price = 100×sqft + 50000×location

With interaction: Price = 100×sqft + 50000×location + 20×sqft×location

The interaction term means: for each extra sqft, the value is 20×location_score higher — location amplifies sqft value!

💡 This captures the synergy that raw features miss.

2.3 Polynomial Features: Capturing Curves with Linear Models

Polynomial features allow linear models to fit non-linear relationships by adding powers of existing features (x², x³, etc.). This transforms a linear model into a polynomial regression.

\[ \text{Polynomial of degree d: } y = \beta_0 + \beta_1 x + \beta_2 x^2 + \beta_3 x^3 + \dots + \beta_d x^d \]
📈 Degree 1 (Linear)
\[ y = \beta_0 + \beta_1 x \]

Straight line — too simple for most real data.

📈 Degree 2 (Quadratic)
\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 \]

U-shaped or inverted-U — captures diminishing returns.

📈 Degree 3 (Cubic)
\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 + \beta_3 x^3 \]

S-shaped — captures increasing then decreasing trends.

⚠️ Warning: The Curse of Dimensionality with Polynomials

With 10 original features, degree=2 creates 55 features! Degree=3 creates 286 features! Always combine polynomial features with feature selection (Module 8).

\[ \text{Number of polynomial features} = \binom{n + d}{d} \]

Where n = original features, d = degree. For n=20, d=3 → 1,771 features!

2.5 Mathematical Deep Dive: Why Interactions Work

📐 The Math Behind Interactions

Without interaction (additive model):

\[ E[Y|X_1, X_2] = \beta_0 + \beta_1 X_1 + \beta_2 X_2 \]

With interaction (multiplicative model):

\[ E[Y|X_1, X_2] = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \beta_3 (X_1 \times X_2) \]

The partial derivative (effect of X₁ on Y) becomes:

\[ \frac{\partial Y}{\partial X_1} = \beta_1 + \beta_3 X_2 \]

Key insight: The effect of X₁ now DEPENDS on X₂'s value!

📈 Polynomial Regression Math

Quadratic model:

\[ y = \beta_0 + \beta_1 x + \beta_2 x^2 \]

The derivative (slope) changes with x:

\[ \frac{dy}{dx} = \beta_1 + 2\beta_2 x \]

Interpretation:

  • If β₂ > 0: curve opens UP (U-shaped, increasing returns)
  • If β₂ < 0: curve opens DOWN (∩-shaped, diminishing returns)
  • Vertex at x = -β₁/(2β₂)

2.6 When to Use Interactions & Polynomials?

✅ Use Interactions When:
  • You suspect synergy between features (e.g., advertising × season)
  • Domain knowledge suggests combined effects
  • Residual plots show patterns across feature combinations
  • Linear model underperforms on test data
  • Features have complementary or multiplicative relationships
✅ Use Polynomials When:
  • Relationship between X and Y is curved (check scatter plot)
  • Diminishing returns or saturation effects exist
  • U-shaped or inverted-U patterns present
  • Residuals show systematic pattern vs fitted values
⚠️ Avoid When:
  • Feature count is already high (risk of overfitting)
  • Sample size is small (n < 10 × new features)
  • Tree-based models already capture interactions naturally
  • You haven't applied feature selection after creation
💡 Pro Tip: For tree-based models (Random Forest, XGBoost), explicit interaction features are LESS critical because trees automatically capture interactions through splits. For linear models, they are ESSENTIAL!

3.1 Why Transform Numerical Features?

Feature transformations modify the distribution or scale of numerical features to make them more suitable for machine learning models. Many models (linear regression, SVM, neural networks) assume normally distributed data or specific scales.

The Core Problem: Real-world data is rarely normally distributed. It often has skewness (long tails), outliers, or non-linear relationships with the target. Transformations fix these issues.
Goals of Transformation
  • Make distribution more symmetric (reduce skewness)
  • Stabilize variance (homoscedasticity)
  • Make relationships more linear
  • Reduce impact of outliers
  • Make data scale-invariant
Signs You Need Transformations
  • Skewness > 1 or < -1 (highly skewed)
  • Residual plots show funnel shapes (heteroscedasticity)
  • Model performs poorly on extreme values
  • Features have vastly different scales

3.2 Log Transformation: The Most Important Transform

\[ x' = \log(x + 1) \quad \text{or} \quad x' = \ln(x) \quad \text{or} \quad x' = \log_{10}(x) \]

The log transformation is the most commonly used transformation for right-skewed data (long tail on the right). It compresses large values and expands small values.

3.3 Box-Cox Transformation: The Optimal Power Transform

\[ x^{(\lambda)} = \begin{cases} \frac{x^\lambda - 1}{\lambda} & \text{if } \lambda \neq 0 \\ \ln(x) & \text{if } \lambda = 0 \end{cases} \]

The Box-Cox transformation automatically finds the optimal power parameter λ that makes the data as normally distributed as possible. It's a family of power transforms that includes log, square root, and inverse as special cases.

3.5 Scaling & Normalization: Bringing Features to Same Scale

Standardization (Z-Score)
\[ z = \frac{x - \mu}{\sigma} \]

Result: Mean = 0, Standard Deviation = 1

When to use: Linear regression, SVM, neural networks, PCA, k-means

Robust to outliers? No (use RobustScaler instead)

Min-Max Normalization
\[ x_{norm} = \frac{x - \min(x)}{\max(x) - \min(x)} \]

Result: Range [0, 1] (or [-1, 1] with feature_range)

When to use: Neural networks (sigmoid/tanh), image pixels, bounded features

Robust to outliers? No (outliers compress the range)

Robust Scaling
\[ x_{robust} = \frac{x - \text{median}(x)}{\text{IQR}(x)} \]

Result: Uses median and IQR (interquartile range)

When to use: Data with many outliers

Robust to outliers? Yes! (uses percentiles)

Scaling Decision Tree:
  • ➡️ Neural networks? → MinMaxScaler [0,1] or [-1,1]
  • ➡️ Linear models / SVM / PCA? → StandardScaler
  • ➡️ Many outliers? → RobustScaler
  • ➡️ Sparse data? → Don't scale (preserve zeros)

3.6 Binning / Discretization: Converting Continuous to Categorical

Binning converts a continuous feature into discrete intervals (bins). This can help capture non-linear relationships and reduce the impact of measurement noise.

Equal-Width Binning
\[ \text{bin width} = \frac{\max(x) - \min(x)}{\text{n\_bins}} \]

Divides range into equal-sized intervals.

Example: Age [0-20], [20-40], [40-60], [60-80]

Sensitive to outliers (one bin may be empty or huge)
Equal-Frequency (Quantile) Binning

Each bin contains approximately the same number of samples.

Example: Income: bottom 25%, 25-50%, 50-75%, top 25%

Better for skewed distributions — ensures balanced bins
Custom / Domain Binning

Bins defined by business rules or domain knowledge.

Example: Age: Child (0-12), Teen (13-19), Adult (20-64), Senior (65+)

Most interpretable for business stakeholders

4.5 Target Encoding: The Secret Weapon for High Cardinality

\[ \text{encoded} = \frac{\text{mean(target)} \times n + \text{global\_mean} \times \alpha}{n + \alpha} \]

Target Encoding replaces each category with the mean of the target variable for that category. With smoothing, it balances category-specific mean with global mean to prevent overfitting.

⚠️ CRITICAL WARNING: Target encoding causes target leakage if done naively. Always use cross-validation or separate holdout data to compute encodings!
Smoothing Formula Explained
  • n = number of times category appears
  • α (alpha) = smoothing parameter (higher = more regularization)
  • Small n → encoded value closer to global mean (less overfitting)
  • Large n → encoded value closer to category mean (more confidence)
💡 Typical α values: 1 to 100. Higher α = more regularization.
Interactive: Target Encoding Demo
Low α (0) → category mean α = 10 High α (100) → global mean
Adjust α to see smoothing effect
def target_encode_smooth(df, category_col, target_col, alpha=10):
    """Safe target encoding with smoothing"""
    global_mean = df[target_col].mean()
    category_stats = df.groupby(category_col)[target_col].agg(['mean', 'count'])
    
    # Apply smoothing formula
    encoded = (category_stats['mean'] * category_stats['count'] + global_mean * alpha) / (category_stats['count'] + alpha)
    return encoded

Haversine Formula
\[ d = 2R \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta\phi}{2}\right) + \cos\phi_1 \cos\phi_2 \sin^2\left(\frac{\Delta\lambda}{2}\right)}\right) \]

Where R = Earth's radius (3959 miles or 6371 km)

💡 This accounts for Earth's curvature — crucial for long distances!
def haversine_distance(lat1, lon1, lat2, lon2):
    """Calculate great-circle distance between two points in km"""
    R = 6371  # Earth's radius in km
    lat1, lon1, lat2, lon2 = map(np.radians, [lat1, lon1, lat2, lon2])
    dlat = lat2 - lat1
    dlon = lon2 - lon1
    a = np.sin(dlat/2)**2 + np.cos(lat1) * np.cos(lat2) * np.sin(dlon/2)**2
    return 2 * R * np.arcsin(np.sqrt(a))

5.1 The Complete Feature Engineering Pipeline

A systematic pipeline prevents mistakes, ensures reproducibility, and avoids the most common—and costly—errors in machine learning.

The Golden Rule: Fit preprocessors (scalers, encoders, bin edges) ONLY on training data. Then transform training, validation, and test data using the fitted objects. 
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer

# Create preprocessor for numerical columns
numerical_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler())
])

# Create preprocessor for categorical columns
categorical_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='constant', fill_value='missing')),
    ('onehot', OneHotEncoder(handle_unknown='ignore'))
])

# Combine into column transformer
preprocessor = ColumnTransformer(
    transformers=[
        ('num', numerical_transformer, numerical_cols),
        ('cat', categorical_transformer, categorical_cols)
    ])

# Full pipeline with model
pipeline = Pipeline(steps=[

])

# Fit on train ONLY, then predict on test

y_pred = pipeline.predict(X_test)

6.3 Interaction Features: Manual Creation

# Manual interaction feature creation
def create_interaction_features(df, feature_pairs):
    """
    Create interaction features from specified pairs.
    
    Parameters:
    -----------
    df : DataFrame
        Input dataframe
    feature_pairs : list of tuples
        List of feature name pairs to interact
    
    Returns:
    --------
    DataFrame with added interaction columns
    """
    df_interact = df.copy()
    
    for feat1, feat2 in feature_pairs:
        # Multiplicative interaction
        col_name = f"{feat1}_x_{feat2}"
        df_interact[col_name] = df[feat1] * df[feat2]
        
        # Ratio interaction (avoid division by zero)
        col_name_ratio = f"{feat1}_div_{feat2}"
        df_interact[col_name_ratio] = df[feat1] / (df[feat2] + 1e-8)
        
    return df_interact

# 4. Target Encoding (with smoothing - SAFE version)
def target_encode_safe(df, category_col, target_col, alpha=10):
    """
    Safe target encoding with smoothing and cross-validation.
    This version prevents target leakage!
    """
    from sklearn.model_selection import StratifiedKFold
    
    global_mean = df[target_col].mean()
    encoded = np.zeros(len(df))
    
    skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
    
    for train_idx, val_idx in skf.split(df[category_col], df[target_col]):
        train_cat = df.iloc[train_idx][category_col]
        train_target = df.iloc[train_idx][target_col]
        val_cat = df.iloc[val_idx][category_col]
        
        # Calculate category means on training fold
        category_means = train_cat.groupby(train_cat).agg(
            mean_target=(train_target, 'mean'),
            count=(train_target, 'count')
        )
        
        # Apply smoothing
        smoothed = (category_means['mean_target'] * category_means['count'] + global_mean * alpha) / (category_means['count'] + alpha)
        
        # Map to validation fold
        encoded[val_idx] = val_cat.map(smoothed).fillna(global_mean)
    
    return encoded

df_cat['city_target_encoded'] = target_encode_safe(df_cat, 'city', 'target', alpha=5)

# Haversine distance function
def haversine_distance(lat1, lon1, lat2, lon2):
    """
    Calculate the great-circle distance between two points
    on Earth (specified in decimal degrees)
    """
    from math import radians, sin, cos, sqrt, asin
    
    R = 6371  # Earth's radius in kilometers
    
    lat1, lon1, lat2, lon2 = map(radians, [lat1, lon1, lat2, lon2])
    dlat = lat2 - lat1
    dlon = lon2 - lon1
    
    a = sin(dlat/2)**2 + cos(lat1) * cos(lat2) * sin(dlon/2)**2
    c = 2 * asin(sqrt(a))
    
    return R * c

# Complete production-ready feature engineering class
import joblib
from abc import ABC, abstractmethod

class FeatureEngineer(ABC):
    """
    Base class for reproducible feature engineering.
    Saves all fitted transformers for production use.
    """
    
    def __init__(self):
        self.fitted_transformers = {}
        self.is_fitted = False
    
    def fit(self, X_train, y_train=None):
        """Fit all transformers on training data only"""
        # Store training column names
        self.training_columns = X_train.columns.tolist()
        
        # Fit numerical transformers
        self.numerical_cols = X_train.select_dtypes(include=['int64', 'float64']).columns.tolist()
        self.fitted_transformers['scaler'] = StandardScaler()
        self.fitted_transformers['scaler'].fit(X_train[self.numerical_cols])
        
        # Fit categorical transformers
        self.categorical_cols = X_train.select_dtypes(include=['object', 'category']).columns.tolist()
        if self.categorical_cols:
            self.fitted_transformers['encoder'] = OneHotEncoder(handle_unknown='ignore', sparse_output=False)
            self.fitted_transformers['encoder'].fit(X_train[self.categorical_cols])
        
        self.is_fitted = True
        return self
    
    def transform(self, X):
        """Transform data using fitted transformers"""
        if not self.is_fitted:
            raise ValueError("Must call fit() before transform()")
        
        X_transformed = []
        
        # Transform numerical features
        X_num_scaled = self.fitted_transformers['scaler'].transform(X[self.numerical_cols])
        X_transformed.append(pd.DataFrame(X_num_scaled, columns=self.numerical_cols))
        
        # Transform categorical features
        if self.categorical_cols:
            X_cat_encoded = self.fitted_transformers['encoder'].transform(X[self.categorical_cols])
            cat_names = self.fitted_transformers['encoder'].get_feature_names_out(self.categorical_cols)
            X_transformed.append(pd.DataFrame(X_cat_encoded, columns=cat_names))
        
        # Create interaction features
        X_combined = pd.concat(X_transformed, axis=1)
        X_combined['sqft_x_bedrooms'] = X_combined.get('sqft', 0) * X_combined.get('bedrooms', 0)
        
        return X_combined
    
    def fit_transform(self, X, y=None):
        """Fit and transform in one step"""
        self.fit(X, y)
        return self.transform(X)
    
    def save(self, filepath):
        """Save fitted engineer for production"""
        joblib.dump(self, filepath)
        print(f"Feature engineer saved to {filepath}")
    
    def load(cls, filepath):
        """Load fitted engineer from disk"""
        return joblib.load(filepath)

7.5 Module 9: Complete Summary

📚 The 10 Most Important Takeaways:
  1. Feature engineering > Algorithm choice: A simple model with great features beats a complex model with poor features.
  2. Always split FIRST: Fit all transformers (scalers, encoders, bin edges) ONLY on training data to prevent leakage.
  3. Interactions capture synergy: Use \( X_1 \times X_2 \), \( X_1 / X_2 \), and \( X_1 - X_2 \) to capture combined effects.
  4. Polynomials capture curvature: \( x^2 \) and \( x^3 \) allow linear models to fit non-linear patterns.
  5. Log transform for skewed data: Right-skewed positive data (income, price, counts) → apply log1p.
  6. Box-Cox finds optimal λ: Automatically finds the best power transformation for normality.
  7. Scale for linear models: StandardScaler for linear regression/SVM, MinMaxScaler for neural networks.
  8. High cardinality → Target encoding: Use with cross-validation to prevent leakage.
  9. Domain knowledge is gold: Distance features, ratios, and business rules often provide the biggest lift.
  10. Validate everything: Use cross-validation to test if new features actually improve performance.
